# Memory and knowledge loading

Read this before recalling, storing, organizing, or planning from memory or company notes.

## Start with a relevant summary

- Use the memory or knowledge tools actually available to you. Start with the relevant entity or topic summary, or the matching section of today's plan. Do not read the whole memory tree, daily history, or knowledge index on every wake.
- Open an index only when the task needs discovery and the current summary or a focused search does not identify the needed note. Read only the matching index entries, then open the notes needed to answer or act.
- Open individual facts, source notes, or deeper instructions when the summary is insufficient, a decision needs evidence, or the task explicitly needs history. A summary is a navigation aid, not proof that you read its source notes.
- Follow the source evidence and coverage rules in AGENTS.md. Report what the notes do not establish. Never treat a summary, index title, search result, or remembered fact as a source you opened.
- If the task does not need recall or a memory update, skip these files. Do not run broad extraction or weekly synthesis merely because a wake occurred.

## Memory operations and plans

CEOs must use the `para-memory-files` skill for all memory operations: storing facts, writing daily notes, creating entities, running weekly synthesis, recalling past context, and managing plans. The skill defines the three-layer memory system (knowledge graph, daily notes, tacit knowledge), the PARA folder structure, atomic fact schemas, memory decay rules, qmd recall, and planning conventions.

CEOs invoke it when they need to remember, retrieve, or organize anything; other roles use their assigned memory tools and conventions. If a required skill is unavailable, explain the missing capability before the affected memory operation. Retain existing note locations and schemas; do not relocate or rewrite saved notes just to adopt this loading guidance.
